# Marketing Frameworks

Ten frameworks that come up constantly in marketing work. Most people can name them; fewer can apply them well or know how strong the evidence behind each one is. This skill does both.

## Main use: websites, marketing plans, social media

Most requests are one of these three jobs. Open the matching playbook first. Each one sequences the frameworks for that channel, gives a framework-to-tactics-to-measures table, an output template, a worked example and common mistakes, and links to the per-framework files for depth.

| Job | Open first |
|---|---|
| Build or audit a website, landing page, pricing page, product page, signup or onboarding flow, CRO review | [apply-websites.md](references/apply-websites.md) |
| Write or review a full marketing plan, strategy or launch plan | [apply-marketing-plans.md](references/apply-marketing-plans.md) |
| Social media strategy, content pillars, calendar, hooks, captions, ads, community, short-form video | [apply-social-media.md](references/apply-social-media.md) |

Then read only the per-framework files the playbook points to. If the job is something else (explain, quiz, a single framework question), use the routing table below.

## How to use this skill

1. **Work out the job.** Is the user asking to *learn* (explain, quiz, compare) or to *do* (plan, write, audit, price)? Doing is the more common and more valuable case.
2. **Pick the frameworks** from the routing table below. Usually one or two, rarely more. Stacking five frameworks onto one problem produces a template, not an answer.
3. **Read only the reference files you need** from `references/`. Each file has the definition, how to apply it step by step, a worked example, common mistakes and an evidence note.
4. **Apply it to the user's actual situation.** Use their product, audience, prices and numbers. If key facts are missing (who the customer is, what the price points are), ask for them or state the assumption you made.
5. **Be honest about evidence.** Some of these are robust models, some are lab findings that shrink in the field, one is folklore. Each reference file has an evidence rating; pass it on when the user is about to bet money or a strategy on it.

Two of these, the Eisenhower Matrix and the Pygmalion effect, are not marketing frameworks in the strict sense (one is about prioritising, the other about management). They are in the set because marketers use them every week.

## Evidence at a glance

| Framework | Type | Evidence |
|---|---|---|
| RACE | Planning model | Practitioner model - useful structure, not a tested theory |
| STP | Strategy model | Foundational, taught everywhere; a process, not a claim to test |
| 4 Ps | Strategy model | Foundational; critiqued as seller-centric (see 4 Cs, 7 Ps) |
| Brand resonance pyramid | Strategy model | Widely used academic model; diagnostic, not predictive |
| Theory of planned behavior | Psychology theory | Good for intention, modest for behavior; well tested but contested |
| Decoy effect | Behavioral finding | Strong with numeric option tables, unreliable with real or visual products |
| Pygmalion effect | Behavioral finding | Real but small, and the famous original study is disputed |
| Zeigarnik effect | Behavioral finding | Memory claim failed to replicate (2025 meta-analysis); "urge to finish" holds up |
| Eisenhower Matrix | Productivity tool | Heuristic - no formal evidence base, very practical |
| Rule of 7 | Marketing heuristic | Folklore - no study shows 7 is the number |

## Output guidance

- **Explaining:** one-line definition, the parts, one concrete example, when *not* to use it. Skip the history unless asked.
- **Applying:** lead with the recommendation, then show the framework as the working underneath (a table often works best). The user wants a better plan, not a lecture on the framework.
- **Quizzing:** ask one question at a time, mix recall with "which framework fits this scenario", and explain each answer.
- **Comparing:** a table with purpose, inputs, output and when to use each.

Write in plain language, without jargon unless the user uses it first. Don't invent statistics. If you cite a number, it should come from the reference file or a source you can name.
